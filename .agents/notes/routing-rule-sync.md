# 主节点路由规则同步

## 需求与所有权

用户确认采用主节点本机统一管理。规则的 `sync` 为面板属性；子节点副本使用 `panelSyncSource` 标识，普通本地/旧远程保存会保留权威副本，编辑器禁用副本修改。仅共享规则组成有序组，API 规则始终第一，共享组优先于子节点本地组。同步全部均衡器及观测器配置，不复制代理出站，不猜测跨节点标签。路由脚本会让核心忽略普通规则，因此与非空同步组互斥并明确报错。

## 持久化与协调

利用现有 Setting 表保存 `routingSyncDesired`（来源、版本、快照）和 `routingSyncReceived`（来源、版本、内容哈希、是否成功应用），不引入模型或迁移。主模板、稳定身份和快照在同一事务保存；共享规则、均衡器或观测器配置改变才递增版本，包括关闭/删除产生的空快照。未启用同步时不产生空快照。

子节点验证引用后，同事务保存合并模板和未应用回执，再调用现有 `RestartXray(false)` 协调。核心运行时优先热更新，失败按原有策略回退；停止核心不启动。只有协调成功才标记应用完成，同版本失败可以继续重试；旧版本忽略、同版本不同内容或不同父节点拒绝。模板锁防止普通保存与同步写入互相覆盖。面板属性统一在运行配置生成时剥离。

同步 RPC 独立于覆盖式旧接口，允许 admin/node-sync 权限；不向旧节点降级覆盖全部路由。启用的下游节点存在时拒绝接收，避免一主多从拓扑中的主节点互相覆盖。

## 分发与恢复

主节点面板保存和路由 API 保存后立即并发发送，最多 8 个并发、单节点 8 秒、整批 30 秒；错误保留节点名、ID 和底层原因，本机期望状态仍保存。每 30 秒后台任务重新发送最新持久化快照，覆盖离线恢复、失败重试和新增节点，无需内存待办状态。子节点已应用同版本直接返回，不写模板、不重启。快照协议置于独立 `internal/routingsync` 包，避免 runtime/service 循环引用。

## 验证

服务测试覆盖版本不增生、停用同步撤回、合并优先级、本地规则保护、来源/版本冲突、引用缺失、离线失败恢复与新增节点补发。真实核心集成检查共享规则立即切换路由、撤回立即恢复本地规则、无进程重启、面板字段不泄漏，以及真实配置拒绝后的同版本重试。生产路由契约覆盖新 RPC 的 admin/node-sync 鉴权；前端检查同步关闭值、远程编辑不暴露开关及受管规则只读。

相关规格见 [routing-rule-sync](../../docs/specs/routing-rule-sync.md)。

## 均衡器同步补齐

原快照只有规则，均衡器在子节点缺失时规则无法安装。复用 Control 增加可选 balancing 权威块；主节点即使没有 sync 规则也保存非空均衡器快照，删除后保留显式空数组。接收端先合并，再验证引用和备用链闭环，事务保存模板及回执；沿用运行态协调和后台重试。没有 balancing 的旧请求保留均衡配置，哈希保持旧格式，以支持升级期间的失败重试。

子节点均衡器及观测器由父节点完整管理，收到的 balancing 保存在回执中，用于普通模板保存保护；接收后不生成向下游广播的快照。_bl_ 为面板已有保留命名空间，按备用链重建回环出站和优先内部规则，删除时清理。普通出站继续使用现有出站同步，未到齐时明确报错并等待重试，不静默回退。新的 RPC 确认包含 balancingApplied，主节点发现旧接口忽略新字段时报告需升级。

测试覆盖独立均衡器保存的版本变化、观测器切换、备用链与本地规则保留、子节点保存保护、完整撤回、缺失引用与环路的原子拒绝；真实核心 RPC 场景检查新增、只改选择器及删除立即改变实际 TestRoute 结果。
