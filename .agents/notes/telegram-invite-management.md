# 邀请码管理

当前码原文仅管理员无缓存接口返回，SQL 写入关闭参数日志；保留使用/吊销/过期时间，清理仅移除孤儿记录。轮转、吊销和绑定使用同一进程锁；消费在事务中带有效期和状态条件原子更新，失败回滚不消费。

此前本地验证重发链接成功，不能证明客户反馈属于操作错误。完整参数自动绑定原本已经存在；本次补充裸 start 的明确提示与诊断日志，以及固定可复查的邀请码管理。深链接路径检查包括旧码失效、新码自动绑定及裸 start 提示。

## 自定义有效期与无限期（2026-10-19）

生成 API 使用 BindCodeInput，validityMinutes 省略/null默认30，0永久，其余1..5256000整数分钟；保留 CreateCode 默认入口兼容现有调用。复用 expires_at=0，无新模型/迁移。读取凭据及事务消费两处同时使用 `(expires_at=0 OR expires_at>now)`，与 hash/used_at/revoked_at 条件用 AND 连接，防止无限期绕过一次性与吊销。列表仅非零时间参与到期判断，0显示永不过期。

生成与轮转复用 RHF/Zod 弹窗：选择客户端、时长/单位或永久；轮转恢复原时长，未确认不改旧码。弹窗及固定列表均可复制，切换客户端不显示另一个客户端的旧结果。新选项只影响本次生成，已有链接有效期不变。
