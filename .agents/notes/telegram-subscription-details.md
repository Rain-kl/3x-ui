# Bot 订阅详情与短时回复

## 订阅与节点

扩展既有 Hooks，以可选订阅 Provider 接口调用当前 SubService；不引入 service -> sub 循环依赖，也不另写归属 SQL。仅 Bot 请求启用节点名收集器，在实际生成正常及外部链接时提取显示名；VMess 读取 ps，普通链接读取 fragment，未携带名称的 MTProto/AmneziaWG 使用当前入站的备注模板兜底。通知和状态占位不进入收集点。mixed 复用订阅展示页 manualMixedNodes，沿用批量节点地址缓存及配额、启用状态过滤。

/subscription 和确认 /reset 后返回订阅地址、可选 mixed 信息及转换/删除提示，按4000字节拆分，逐片发送并记录日志。/nodes 只返回一行一个名称，仍要求有效绑定；加入 Telegram 原生菜单。新增内置命令后自定义项上限改为93；已有94项配置最多展示前93项并记录日志，旧自定义 nodes 被内置优先覆盖。

## 删除队列

独立 TelegramMessageDeletion 表，以 Bot Token 哈希、chat_id、message_id 唯一。发送成功后持久化30秒删除期限，单个受生命周期管理的 worker 每秒查询至多20条到期任务，单次API调用超时5秒。完成后删除队列项、保留原始管理日志；失败按原有API退避策略最多尝试5次。已经删除视为成功，终止错误及重试耗尽记录具体失败。取消面板/重启不丢队列任务；Bot身份隔离避免 Token 切换误删其他 Bot 消息。48小时仍未处理的任务清理并记录过期原因。

网络不可用、API限流或面板停止期间无法保证精确30秒；恢复后继续到期任务。管理侧消息日志按原保留周期保存，不随 Telegram 删除。
