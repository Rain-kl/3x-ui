# 路由本地规则丢失与固定出站标识

## 已复现原因

1. `/server/outbounds` 在锁外读取整份模板，再调用锁内 Save，旧整份模板可覆盖刚新增的本地规则。keepManagedRouting 仅保留父节点组，因此表象为仅剩同步规则。普通浏览器长时间停留的旧页面也可产生相同覆盖。
2. 远程节点编辑没有请求代次/节点检查，A 的迟到响应可覆盖 B 的编辑状态，保存时使用 B 的 nodeId 和 A 的规则。
3. 空/null 的 panelSyncSource 在所有权筛选时被当作“有字段但非有效父节点”，导致规则静默丢弃。

## 修复边界

局部模板变更通过 editTemplate 在锁内完成最新读取、修改和提交。出站同步、入站重命名/删除与 Warp 更新共用该路径。完整编辑提供 expectedXraySetting；路由编辑保留原始 expectedRoutingRules，经新 checked RPC 做锁内 JSON 等价前置校验。旧节点 checked RPC 返回 404，客户端不得降级。旧无前置条件接口仍保留用于兼容外部调用，旧客户端需升级才能获得浏览器冲突保护。

前端异步请求按节点和代次隔离；切换、卸载和完成后刷新均不允许旧节点响应改写当前节点。空归属规范为本地，非法类型报错，不默默过滤。

## 固定出站标识

核心 tag 本身就是路由关联 ID，增加独立显示 remark；新建出站使用 ob-UUID，panelId 与 tag 保持一致，编辑/import connection 不改变 ID。旧标签直接作为已有 ID，避免破坏均衡器前缀与观测器引用。主子模板保存保留名称和 ID，运行配置剥离面板元数据。订阅来源沿用已有身份->tag 映射，只保存供应商名字到 remark。

## 验证与部署

服务回归覆盖旧整份模板拒绝、局部出站更新保留本地规则、父节点刷新、归属空值、ID 与备注分离、运行字段清理。控制器验证缺失/旧规则基线无写入，runtime 验证旧节点无降级，前端重放 A/B 请求乱序并验证 B 保存的内容与基线。

节点鉴权白名单的契约清单包含 checked RPC。新增回归用例显式隔离 XRAY_LOCATION_ASSET，避免核心出站校验自动设置进程环境后污染地理库用例；随机种子 1793677730321189506 已先复现污染，再验证修复。

主子面板均需升级。无法从现存同步快照恢复子节点已丢的本地规则，应使用丢失前数据库备份/导出。修复不猜测重建历史规则。
