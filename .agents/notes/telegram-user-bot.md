# 用户 Telegram Bot 实现说明

## 需求与结构

独立用户 Bot Token，既有管理员 Bot 接收咨询并以回复原消息的方式答复。用户账号与客户端双向唯一，不复用旧版可关联多个客户端的 tg_id 字段。设计见 [行为规格](../../docs/specs/telegram-user-bot.md)。

业务与 Telegram REST 适配位于 internal/telegramuser；Web Service 通过 Hooks 注入既有订阅更新、汇总流量和管理员网络配置，避免该包反向依赖 Web。面板启动/停止/重载负责唯一的用户轮询器，管理员仍使用既有接收循环。

## 数据与身份

新增配置、绑定、绑定码、会话、消息、运行日志、管理员回复映射七个模型；allModels 与 migrationModels 同步注册，支持跨数据库迁移。无强制客户端外键，删除客户端后历史可查，原绑定可解绑。

绑定码为随机 128 位值，30 分钟有效，一次性消费且只存 SHA-256。绑定订阅链接仅解析已配置公开地址的标识，不请求用户 URL。歧义订阅标识拒绝绑定。事务及双方唯一索引禁止静默覆盖。重置订阅和解绑需用户确认，重置复用 ClientService/Runtime。

Token 单独存配置表，不进入通用设置导出与前端返回。保存 Token 的 ORM 操作关闭 SQL 日志；轮询游标用 Token 摘要条件更新，错误中的 Token/代理凭据脱敏。订阅链接、绑定凭据与指令返回中的敏感内容不写明文消息日志。

## 聊天、通知和附件

所有收发和错误记录入库。消息分页；会话未读游标只推进到实际展示的消息，避免轮询误读。网页支持文字、附件、回复、查看媒体和下载。管理员 Bot 回复通过 Token 摘要、Chat ID 和 Message ID 持久化映射定位，不能根据消息文本指定用户。

Telegram 不允许跨 Bot 复用 file_id，桥接先从源下载再向目标上传。二进制不长期存库；下载和网页上传限 20 MiB，面板并发缓冲限两个。管理员鉴权下载隐藏 Token 并禁止缓存。附件桥接失败保留原记录、写明错误，并尝试给管理员文字提示。

发布通知与定向发送队列在同一事务写入；受众按客户端或当前分组批量查询，发送前再次验证版本、发布状态和绑定。撤回、换绑和删除后的旧通知取消。咨询与管理员回复优先于批量通知，带超时、按接收者限速和最多五次有界重试。未发送记录可跨重启恢复；网络断开但 Telegram 已受理等不确定场景可能重复投递，不能保证严格只送一次。同步发送中断标记为失败，提示管理员检查是否送达。

日志和消息独立保留天数；每小时清理并支持手动按天/全部清理，保留绑定、待发送和发送中记录。回复映射只在关联原消息已清理后删除。

## 接口与界面

侧边栏 Telegram：消息、日志、设置三个页签；设置含绑定管理、一次性码与链接复制。15 个管理接口复用管理员鉴权/CSRF；节点同步令牌不扩大权限。Go 模型生成前端 Zod/类型，接口注册和前端/文档站 OpenAPI 同步。

既有源文件修改用 FORK(telegram-user-bot) 标记；FEATURES.md 同步登记。

## 检查与限制

按用户要求不新增、不运行测试，不向真实 Telegram 用户发送验证消息。Go 全库编译及 golangci-lint、前端 typecheck/lint/生产构建均通过；接口文档已重新生成。尚未以真实 Token 验证 Telegram 网络交互。

需先在设置中配置用户 Bot Token 和公开订阅地址前缀；管理员咨询转发还需现有管理员 Bot、Chat ID 和接收服务启用。历史 tg_id 不自动视为用户授权；用户需要绑定。附件取回依赖对应 Bot 仍可访问 Telegram 文件，换 Bot 后旧附件可能不可取回。

## 2026-10-18：移除底部快捷键盘

按用户要求删除自定义回复键盘，仅保留 setMyCommands 注册的原生 / 指令提示。普通指令响应发送 remove_keyboard，让旧版本已展开的键盘在下次普通指令响应时收起；重置、解绑的消息内确认按钮保留。绑定成功提示同步改为输入 /。本次仅编译相关包，不运行测试或发送真实 Bot 消息。

## 2026-10-18：匿名聊天控制与移除清除 Token

用户要求去除冗余 Token 清除操作，前后端 clearToken 字段及语言词条均删除；空值继续保留 Token，新值覆盖。新增 allowAnonymousChat 配置，默认 false，旧配置通过自动迁移同样关闭。设置保存后重载接收器。

接收端复用本次已查询的客户端绑定，未绑定的普通文本、附件和编辑消息以 restricted 角色保留排障记录，不转发也不计待回复未读；指令和绑定凭据仍正常处理。队列发送端重新查询当前绑定并与管理员转发总开关共同校验，阻止关闭匿名聊天或解绑后仍转发旧咨询；数据库异常保留队列并记录错误，不能放行。网页历史仍保留完整收发与限制原因。

接口文档、Go 生成模型、前端 Zod 和 13 种语言同步更新。本次不新增测试，不向真实用户发送消息；提交前执行编译和静态检查，推送沿用现有 pre-push 护栏。
