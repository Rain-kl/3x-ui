# 订阅访问风控

所有 raw/HTML/info/JSON/Clash/Mihomo 路径在渲染前执行同一中间件。真实来源仅从可信代理链解析；有效客户端查询、IP 窗口、阈值判断和访问事件由串行写事务统一提交，第六个不同 IP 即使并发也先阻断再执行停用。窗口压缩为哈希+IP最后时间，避免每请求扫描历史日志；不保存完整订阅 token。

使用现有客户端停用及 Runtime，持久化风险与独立收件人通知队列。远端必须确认，离线和失败维护任务重试；未确认时管理员收到待处理状态，不宣称代理已全部停止。用户停用通知仅在确认停用后排队，并在发送前再次检查绑定归属。通知独立于用户 Bot 轮询，发送结果写入 Telegram 消息日志，最多十二次自动尝试后允许手动重发。成功消息不重发；外部发送成功但进程未保存结果的极小崩溃窗口仍可能重复投递。

访问表默认保留三十天，清理仅删访问事件；风险、IP 窗口不随手动清理解除。UI 日志分页，风险/失败通知显示最近一百条，风险客户端名称批量查询，不逐项查表。四张新表同时登记两类迁移和全库 ZIP。
