# 定向订阅通知

主控保存通知事件，受众使用客户端不可变 ID 或当前分组名称。一个订阅可能关联多个客户端，因此查询当前订阅身份后以 Map 匹配已发布通知，结果按 sort_index/id 稳定排序并自然去重。受众名单只在管理员 API 返回，公开网页/info 只含命中的标题、正文和发布信息。数据库模型同时注册 allModels 和 migrationModels。

通知只属于订阅展示层，不创建入站、不调用 Runtime 或同步到子节点。raw/Clash 的通知项使用保留域 notification.invalid:1，无真实服务；JSON 的独立配置只包含 blackhole 出站并覆盖路由，避免借用用户现有代理身份。Clash 从选择组剔除通知项。旧有到期/配额提示先计算，最后统一前置通知，避免到期分支吞掉通知。网页-only 事件不进入自动订阅；正常网页配置列表保持真实节点，通知在上方单独展示。

管理员表单与列表使用 React Hook Form/Zod、TanStack Query，客户端选择采用轻量分页搜索和所选 ID 批量回填，不拉取全量凭据。草稿与撤回可保留已失效受众；发布时重新校验受众存在，避免删除客户端或分组后无法撤回。分组重命名后需要重新选择通知分组，不静默扩散到其他用户。

本次执行 Go 编译与 golangci-lint、前端 typecheck/lint/格式检查及生产构建，并生成 Go 契约、两份 OpenAPI 和 docs API 页面。通知功能尚未运行自动化或真实订阅客户端验证；不能将编译和静态检查表述为端到端验证通过。
