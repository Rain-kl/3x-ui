# 定向订阅通知

主控保存通知事件，受众使用客户端不可变 ID 或当前分组名称。一个订阅可能关联多个客户端，因此查询当前订阅身份后以 Map 匹配已发布通知，结果按 sort_index/id 稳定排序并自然去重。受众名单只在管理员 API 返回，公开网页/info 只含命中的标题、正文和发布信息。数据库模型同时注册 allModels 和 migrationModels。

通知只属于订阅展示层，不创建入站、不调用 Runtime 或同步到子节点。按用户反馈统一改为标准 VLESS/TCP、127.0.0.1:1、无 TLS、固定占位 UUID，以免被客户端按不支持的协议过滤。JSON 保留 VLESS 主出站以供识别，另用 blackhole 出站和覆盖路由阻断实际转发。Clash 通过占位 UUID 和地址识别通知并从选择组剔除。旧有到期/配额提示先计算，最后统一前置通知，避免到期分支吞掉通知。网页-only 事件不进入自动订阅；正常网页配置列表保持真实节点，通知在上方单独展示。

管理员表单与列表使用 React Hook Form/Zod、TanStack Query，客户端选择采用轻量分页搜索和所选 ID 批量回填，不拉取全量凭据。草稿与撤回可保留已失效受众；发布时重新校验受众存在，避免删除客户端或分组后无法撤回。分组重命名后需要重新选择通知分组，不静默扩散到其他用户。

本次执行 Go 编译与 golangci-lint、前端 typecheck/lint/格式检查及生产构建，并生成 Go 契约、两份 OpenAPI 和 docs API 页面。通知功能尚未运行自动化或真实订阅客户端验证；不能将编译和静态检查表述为端到端验证通过。

## 2026-10-18：客户端与分组并选、全选

通知编辑器移除二选一，两个选择器同时展示，新保存使用 targetType=both。后端保留旧 clients/groups 语义，旧通知无需迁移，编辑时仅恢复原有效目标并转为 both。并集匹配同步用于订阅网页/节点、Telegram 发布队列、绑定补发、主动获取历史和发送前校验；SQL OR 查询每个绑定只取一行，重复命中不会重复推送。

客户端全选循环请求已有分页接口，不受搜索和已加载页限制，成功完整取回后才替换选择；组全选使用全部组列表。提供分别清空，保留每类 2000 上限，超限或网络错误显示错误且保留原选择。全选为明确目标快照，不隐式永久广播。

不新增或单独运行测试；编译、静态检查、接口文档生成后提交推送，沿用现有 pre-push 护栏。

## 2026-10-18：通知标题可留空

按用户要求允许不填标题只发正文：后端保存校验放宽为标题可选（≤120 字）且正文必填；Telegram 投递文本在空标题时直接使用正文，不再拼接标题与空行；占位节点名称在空标题时不再出现 "· " 分隔符。编辑器标题取消必填与星标，通知列表与订阅网页在空标题时不渲染标题行。既有带标题通知行为不变。不新增或单独运行测试；Go 编译/vet/gofmt 与前端 typecheck/oxlint 及相关 vitest 通过；internal/web/service 包测试因既有 client_bulk 测试与 BulkAdjust 签名不匹配无法编译，本次未运行该包测试。

## 2026-10-19：发布与 Telegram 推送动作分离

NotificationSaveInput 嵌入既有通知字段并增加请求专用 pushTelegram，缺省为 false；不加数据库列、不回填到通知记录。编辑器和列表分别提供普通发布及“发布并推送 TG”；草稿/撤回明确传 false，选择推送时必须已发布。仅 true 分支调用原定向入队方法，保留受众并集、发送限速、重试与版本验证；显式推送但用户 Bot 未配置/启用时返回错误并回滚发布事务。已发布通知可主动再推送，后续普通保存不会自动继承。

首次绑定补发和 /notifications 获取历史仍按全部当前可见通知处理：新标志只控制本次发布动作的主动投递。API 请求采用单独生成的 DTO，不将 transient 字段塞到持久化模型。新旧接口调用省略该字段均默认为不推送。
