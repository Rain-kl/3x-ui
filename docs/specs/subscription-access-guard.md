# 订阅访问审计与泄露防护

所有实际订阅入口（raw、HTML、信息JSON、JSON、Clash、Mihomo及别名）在响应前执行同一防护。有效订阅记录客户端、来源IP、UTC时间、方法、格式和响应状态，不保存完整订阅链接或Token，只保存哈希；未知随机Token不落库，避免无效请求撑满日志。HEAD记审计但不参与获取订阅的IP阈值；GET按最近10分钟窗口内不同IP统计，超过5个（第6个）立即阻断本次获取。

IP规范化，IPv4映射IPv6合并，剔除端口。仅当TCP对端属于显式配置的 trustedProxyCIDRs 才解析代理IP头，从最右侧不可信代理确定来源；不信任公网请求自带 X-Forwarded-For/X-Real-IP。窗口记录以订阅哈希+IP压缩，重复IP只更新最后访问时间，不逐条扫描完整日志计算阈值。状态和计数与审计记录事务提交，复用串行数据库写队列防并发第6请求漏判；服务重启不丢计数。

触发后复用 ClientService.BulkSetEnable(false) 停用所有命中该订阅的客户端，沿用节点Runtime更新，阻止订阅获取及代理新连接。处置失败持久化错误并自动重试，风险状态及通知状态在审计界面可见。用户消息为「你的订阅链接已被泄露,系统已自动停用, 请联系管理员解决。」；仅给命中客户端的当前Telegram绑定发消息，同时通知配置的管理员Bot。通知按收件人排队并去重，独立于用户Bot轮询开关重试，永久错误保留并可手动重试。

管理员在现有客户端管理中恢复客户端后，下一次有效访问结束该订阅的封锁状态并重建10分钟窗口；不自动恢复被停用客户端。日志清理不解除封锁或重置活动窗口。访问日志默认保留30天，支持分页按客户端/IP/日期查询、主动清理；完整审计ZIP包含访问、防护和通知数据。定时维护清理过期窗口、日志及已完成通知，并重试处置与通知，无自研脚本运行器。

普通手动停用但未触发泄露风控的订阅，继续沿用现有停用说明页面和空配置响应；泄露风控状态会阻断订阅输出。HWID 状态对已阻断与未知订阅均返回 404，不暴露该端点的有效订阅存在性。访问日志在实际提供订阅的面板查看，子节点独立提供订阅时也可查看自己的访问审计。
