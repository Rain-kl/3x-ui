# mixed 客户端统一

## 行为与身份

mixed 加入本机/子节点部署、编辑、克隆白名单；子节点使用同一客户端关联、账号同步与权限撤销流程。新建 mixed 以现有 ClientRecord/ClientInbound 为唯一用户来源，配置使用 settings.clients；鉴权必须为 password，零客户端时拒绝访问，不能回退为匿名代理。

客户端增加可选 username，mixed 为空时使用 email；password 复用现有密码。username 是外部鉴权名，email 是面板身份，运行态 email 按入站编码以隔离计费；不能把编码后的身份用作 HTTP Basic 用户名。校验同一入站内用户名唯一、非空、不含冒号、SOCKS5 用户名/密码 UTF-8 字节长度均不超过 255。HTTP CONNECT、普通 HTTP、SOCKS5 TCP/UDP 共享鉴权与客户端身份。

启用状态、到期、总配额与节点配额沿用现有客户端流程，动态增删通过 Runtime 分发；账户增删影响 HTTP 和 SOCKS 两条链路。运行配置只包含启用的客户端及其独立限速。旧核心不能忽略 clients 后继续运行或变成匿名代理；启动和热应用均检查最低功能版本并明确报错。

## 迁移与兼容

新增 username 列使用现有数据库迁移机制。旧 password mixed 账号在保存/导入时迁移到客户端和关联表，保留原用户名/密码；生成稳定且不覆盖其他客户的 email，并创建默认流量记录。账号明细、关联和入站 settings 的修改在同一事务中完成，重复保存不重复创建。旧 noauth 入站保持既有匿名行为但不可关联客户端；将其改为客户端模式必须显式开启密码鉴权。兼容导入旧 accounts，保存时转换为同一客户端模型，运行态不并存两套用户来源。

入站表单复用现有客户端编辑/附加入口。客户端凭据页展示 mixed 用户名/密码；详情提供 HTTP/SOCKS5 连接信息。手工旧账号不因用户名冲突合并到其他客户端。核心需提供 clients 身份映射、共享的线程安全用户表和 UserManager 接口；主从面板与定制核心需共同升级。

## 检查场景

从主控创建/编辑/克隆 mixed 到子节点；不同客户共享端口、同客户多入站计费隔离；HTTP/SOCKS 身份一致；重复用户名拒绝；最后一名客户撤销后不匿名放行；旧账号迁移保留凭据并幂等；过期、禁用、节点配额、密码修改可下发；旧核心明确拒绝托管配置。

## 订阅展示

控制端客户端二维码弹窗也提供独立的 mixed 手动配置折叠项，展示当前客户端关联的 mixed 入站及地址、用户名、密码、HTTP/SOCKS5 复制入口。复用已加载的客户端和入站信息，不逐节点请求；地址遵循节点、监听和自定义分享地址策略。控制端供管理员查看已配置凭据，不以订阅服务是否开启或是否有普通订阅链接为显示条件；不改变自动订阅内容。

mixed 始终排除普通链接、JSON、Clash 自动订阅。只有订阅展示页及其信息接口提供独立的手动配置区域，列出该订阅身份关联且启用的 mixed 入站、用户名、密码以及 HTTP/SOCKS5 复制地址；不把这些地址加入自动导入或“复制全部配置”。仅 mixed 的用户也可正常打开展示页，流量和有效期继续按统一客户端统计。禁用、过期、总流量或入站配额耗尽时不展示可用凭据；只查询当前订阅的关联，不能展示其他用户的账号。地址遵循入站现有节点/监听/自定义地址选择，IPv6 与凭据做正确编码。
