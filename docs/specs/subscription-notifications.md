# 定向订阅通知

## 管理与状态

主控侧边栏新增“通知”，管理员可创建事件，填写标题、纯文本正文、排序值，选择多个客户端或多个用户分组，并选择是否发布到节点。支持保存草稿、发布、编辑已发布内容、撤回和删除。只有已发布事件对用户可见；保存修改后下次订阅请求立即使用新内容，无需重启核心或子节点。排序值越小越靠前，相同值按事件 ID 排序。

事件由面板数据库持有，不创建真实入站、客户端关联或运行态代理，也不向子节点部署服务。客户端以不可变 ID 定向；分组按当前分组名称动态匹配，新加入者可见、离开者不可见；分组重命名后需修改通知目标。一个订阅 ID 对应多个客户端时取命中的通知并集，每条只显示一次。空目标不能发布，禁止隐式广播全部用户。

## 订阅输出

订阅网页在真实配置列表之前显示命中的通知标题与完整正文，保留换行、不渲染 HTML。网页及 info 接口只输出该订阅命中的公开内容，不输出受众名单。保留现有订阅身份与访问校验；通知不使不存在的订阅 ID 变为有效。

勾选“发布到节点”的通知额外在 raw/base64、Xray JSON、Clash/Mihomo 自动订阅中生成标准 VLESS 占位项，地址为 `127.0.0.1`、端口 1，使用固定的占位 UUID、TCP、无 TLS、`encryption=none`，避免客户端因不支持占位协议而过滤。排序在普通节点及已有状态提示节点之前，名称为通知标题与正文摘要；完整正文仍在网页展示。JSON 配置保留 VLESS 主出站供客户端识别，并用 blackhole 路由阻断实际转发。Clash 的真实代理选择组不包含这些占位项，避免默认选择通知。未勾选者仅网页显示。撤回/删除后下次刷新订阅不再返回，客户端需更新订阅才能移除旧副本。

## 数据与接口

新增 SubscriptionNotification 模型，包含标题、正文、客户端 ID/分组列表、受众类型、发布到节点开关、发布状态、排序和时间戳；SQLite/PostgreSQL 自动建表并同时登记 allModels 与 migrationModels。管理 API 包括分页列表、保存、删除及仅含客户端 ID/标识的分页受众搜索；沿用管理员鉴权和 CSRF，节点同步令牌不获得通知管理权限。

请求内一次读取订阅客户端身份/分组、一次读取已发布通知，在内存用 Map 匹配和去重，不按通知或节点逐条查询。限制标题、正文和受众数量，管理列表及客户端选择分页；所有数据库和校验错误携带上下文返回。

## 验收场景

客户端和分组受众隔离；同一订阅多身份去重；草稿不公开、发布立即可见、撤回删除后消失；网页-only 不进入自动订阅；多通知顺序在普通节点之前；raw/JSON/Clash 占位项无法代理且不参与选择组；纯文本脚本内容不执行；仅 mixed 用户和过期订阅保留通知；无效订阅不可探测通知；模型迁移及接口登记一致。
