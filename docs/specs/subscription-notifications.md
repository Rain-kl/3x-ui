# 定向订阅通知

## 管理与状态

主控侧边栏新增“通知”，管理员可创建事件，标题可留空，填写纯文本正文、排序值，同时选择多个客户端和多个用户分组，并选择是否发布到节点。标题留空时只发布正文，订阅网页、占位节点名称和 Telegram 投递不再出现标题行、分隔符或空行。支持保存草稿、发布、编辑已发布内容、撤回和删除。只有已发布事件对用户可见；保存修改后下次订阅请求立即使用新内容，无需重启核心或子节点。排序值越小越靠前，相同值按事件 ID 排序。

事件由面板数据库持有，不创建真实入站、客户端关联或运行态代理，也不向子节点部署服务。客户端以不可变 ID 定向；分组按当前分组名称动态匹配，新加入者可见、离开者不可见；分组重命名后需修改通知目标。一个订阅 ID 对应多个客户端时取命中的通知并集，每条只显示一次。客户端和用户组为并集，命中任一项即可接收，重叠不重复。空目标不能发布，禁止隐式广播全部用户。新编辑器统一保存 targetType=both；旧 clients/groups 类型保留原语义，编辑保存后转为并集。

客户端和用户组选择器各提供全选和清空；客户端全选分页读取全部客户端而非仅选已加载页，不受搜索词影响；分组全选包含全部当前分组。全选保存的是点击时的明确 ID/名称快照，未来新增客户端不会自动纳入直接客户端列表，已选分组仍动态匹配。保留每类最多 2000 个目标的现有限制，超限或加载失败明确报错并保留原选择，不静默截断或保存半成品。

## 订阅输出

订阅网页在真实配置列表之前显示命中的通知完整正文，填写了标题时同时显示标题，保留换行、不渲染 HTML。网页及 info 接口只输出该订阅命中的公开内容，不输出受众名单。保留现有订阅身份与访问校验；通知不使不存在的订阅 ID 变为有效。

勾选“发布到节点”的通知额外在 raw/base64、Xray JSON、Clash/Mihomo 自动订阅中生成标准 VLESS 占位项，地址为 `127.0.0.1`、端口 1，使用固定的占位 UUID、TCP、无 TLS、`encryption=none`，避免客户端因不支持占位协议而过滤。排序在普通节点及已有状态提示节点之前，名称为通知标题与正文摘要，标题留空时仅用正文；完整正文仍在网页展示。JSON 配置保留 VLESS 主出站供客户端识别，并用 blackhole 路由阻断实际转发。Clash 的真实代理选择组不包含这些占位项，避免默认选择通知。未勾选者仅网页显示。撤回/删除后下次刷新订阅不再返回，客户端需更新订阅才能移除旧副本。

## 数据与接口

新增 SubscriptionNotification 模型，包含标题、正文、客户端 ID/分组列表、受众类型、发布到节点开关、发布状态、排序和时间戳；SQLite/PostgreSQL 自动建表并同时登记 allModels 与 migrationModels。管理 API 包括分页列表、保存、删除及仅含客户端 ID/标识的分页受众搜索；沿用管理员鉴权和 CSRF，节点同步令牌不获得通知管理权限。

请求内一次读取订阅客户端身份/分组、一次读取已发布通知，在内存用 Map 匹配和去重，不按通知或节点逐条查询。限制标题、正文和受众数量，管理列表及客户端选择分页；所有数据库和校验错误携带上下文返回。

## 验收场景

客户端和分组受众隔离；同一订阅多身份去重；草稿不公开、发布立即可见、撤回删除后消失；网页-only 不进入自动订阅；多通知顺序在普通节点之前；raw/JSON/Clash 占位项无法代理且不参与选择组；纯文本脚本内容不执行；仅 mixed 用户和过期订阅保留通知；无效订阅不可探测通知；模型迁移及接口登记一致。

## 发布与 Telegram 推送分开

通知编辑器及列表提供两个明确操作：「发布」仅更新订阅网页/所选通知占位节点，不主动发送 Telegram；「发布并推送 TG」保存为已发布状态，并在同一事务内向匹配且已绑定的 Telegram 用户加入发送队列。草稿和撤回不推送。已发布通知可再次使用该按钮明确发起新一轮推送；已失效的旧版本排队消息沿用版本检查取消。

保存接口新增请求专用布尔字段 pushTelegram，省略或 false 均为普通发布，不持久化该字段、不从旧通知状态继承。仅 published=true 且 pushTelegram=true 时推送；草稿携带推送标志拒绝。显式要求推送但用户 Bot 未配置/未启用时，返回具体错误且通知保存事务回滚，不能显示推送成功。受众仍为客户端与用户组并集，重叠只发送一次；消息投递、重试和日志沿用现有队列。没有绑定的用户不产生发送任务。

该选项控制本次发布是否主动推送，不改变首次绑定补发历史通知及用户 /notifications 主动查询全部已发布通知的现有规则。
