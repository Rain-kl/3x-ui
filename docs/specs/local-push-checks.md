# 本地推送前检查

## 目标与入口

通过现有 Husky 的 pre-push 钩子，在 git push 传输提交之前执行本地检查。检查不通过时返回非零状态并阻止推送，不降低远程 CI 的验收要求。提供 make push-check，手动检查当前已提交的 HEAD；手动检查不推送。

## 检查对象与隔离

钩子读取 Git 提供的所有 ref 更新，按实际 local SHA 解析到提交并去重，检查各个待推送提交；只删除远程 ref 或没有更新时直接结束。支持分支及附注标签，不用当前工作目录替代待推送对象。在独立临时 Git 工作树中安装锁定依赖、生成和构建，结束后移除该临时工作树；主工作区的未提交内容和已有依赖不被改写。生成文件检查相对于该提交，缓存下载的核心和本地日志放到已忽略的 .cache/push-checks。

## 默认检查

1. 工具版本符合 go.mod、.nvmrc 和 frontend/package.json；所有 pnpm/action-setup 步骤明确找到具有版本声明的 package.json，防止前端位于子目录却读取根目录配置。
2. 首先运行已有数据库模型清单一致性、API 路由登记等契约检查，尽早发现模型漏登记、接口漏文档。
3. pnpm 冻结锁文件安装；Go 和前端静态检查、前端格式、所有前端单元与组件测试、前端构建和 Storybook 构建。重新生成 Zod/类型/示例/OpenAPI，并核对前端和文档 OpenAPI 一致及文档生成结果；生成漂移导致失败。文档生成只安装必需依赖，跳过不参与生成的可选平台二进制。
4. 全部 Go 包测试及构建；按 release/validate-core 的范围执行审计/节点竞态检查。解析与 CI 相同的最新稳定 feat 核心，检查发布资产可下载，校验本平台核心下载的摘要和版本，并运行真实核心 trafficlog 与 API 集成测试，缺少二进制时不把 SKIP 视为验证通过。
5. 执行二开移除守卫。浏览器 Storybook 与 PostgreSQL 等外部环境依赖仍由完整 CI 验证，本地默认检查明确报告这些覆盖边界；配置了专用 PostgreSQL 测试 DSN 或请求完整浏览器检查时可运行对应环境测试。

每一阶段有明确名称，保留日志，失败报告阶段和日志路径。工具缺失、错误版本、网络校验失败或任一命令失败均阻止推送，不自动改文件或修复代码，不自动推送。Git/Husky 的显式跳过能力不被包装成验证成功；本地检查不能保证远程环境和未来依赖状态完全相同。

## 验收

省略跨数据库模型登记、生成文件未提交、错误 pnpm 配置、失败测试均可被拦截。脏工作区不污染待推送提交的结果，非 HEAD 分支和多个提交 tip 分别检查，删除 ref 不启动检查。失败时主工作区保留原内容，临时工作树被清理，原提交历史不变。安装依赖启用现有 Husky 后钩子自动生效；首次启用需完整运行一轮检查。
