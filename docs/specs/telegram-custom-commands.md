# 用户 Bot 自定义指令

## 行为

Telegram 管理页面新增独立「自定义指令」Tab。管理员可新增、编辑、启停、删除指令，并配置指令名称、Telegram 菜单说明和纯文本回复。列表顺序即菜单顺序，最多94项（加6项内置菜单不超过Telegram的100项限制）。无需重启 Bot。

名称可输入前导 /，保存时去掉 / 并转为小写；规范名称限1–32个ASCII小写字母、数字或下划线。不允许重复或覆盖 start/help/subscription/reset/usage/notifications/bind/unbind。菜单说明1–256字符，回复1–4096字符，不执行模板、脚本或HTML。

内置指令优先。自定义指令对已绑定和未绑定用户均提供静态回复，沿用现有黑名单、指令日志、消息发送日志和键盘收起行为，不转发为聊天。禁用/删除后不再匹配。命令参数不影响静态回复。

## 状态与接口

独立 TelegramCustomCommand 表保存名称主键、说明、回复、启用状态和排序。注册面板模型与跨库迁移模型。GET /panel/api/telegram/commands 读取有序列表；POST 同路径原子替换列表，管理员鉴权及 CSRF 沿用 Telegram 管理 API。完整校验后才写入，失败不改变旧配置，并记录配置更新日志。

回复每次按名称查询已保存的启用项，保存立即生效。Bot 在每轮长轮询前读取菜单，只在内容改变时调用 setMyCommands；失败记录错误并在后续轮询重试，正常空闲情况下约25秒更新。停用 Bot 时仍可编辑，启动后同步菜单。无需更改 Bot Token 或重启收件器。

## 验收场景

新增指令后匿名及绑定用户得到相同文本；菜单包含内置与启用项；编辑即生效，停用/删除不再返回原回复；保留多行与链接；重复、保留名称、非法字符、长度越界和超量拒绝且不覆盖旧列表；重启与跨库迁移保留指令；菜单同步失败不阻止正常处理消息且会重试。
