# 多入站计费快照完整性

## 规则

主节点主动拉取子节点入站列表。用于计费的 `ClientStats.Up/Down` 必须来自该客户端在该入站的 `client_inbounds` 原始计数；`client_traffics` 总账只能补充客户端生命周期信息，不能作为原始入站计数的后备值。

读取客户端关联、补齐共享总账或读取原始计数失败时，完整列表、单入站详情和精简列表均返回带查询上下文的错误。主节点拒绝失败响应，不改变总账及同步基线，下一次成功拉取继续计算增量。

仅返回该入站当前关联客户端的统计。旧共享统计残留不作为当前入站计量。对仍关联的统计，如果原始计数缺失，应拒绝快照，不能用零或总账填补，避免恢复后重计历史。

## 验收

- 1× 同客户端多入站，读取原始计数失败及恢复，不能增加总账或改变同步基线；恢复后的真实新增流量只计一次。
- 倍率不为 1 时也不允许总账作为原始计数回退。
- 关联读取、共享统计补齐及原始计数查询错误必须带上下文传播到调用者。
- 关联删除或原始行缺失不能把残留总账伪装为该入站原始用量。
- 正常多入站统计、生命周期字段、真实计数重置及重复快照保持正确。

## 部署

主子节点均升级。历史已扣用量和审计归档不自动改写；没有足够证据自动区分历史真实流量和错误增量。
